# Master implementation execution

The implemented pipeline preserves the Stronghold-centered 2688-block Overworld square and exact fractional-center 1024-block Nether square. **Both Fortress and Bastion are required in the final Nether square.** Missing predictions remain recoverable pending work. Independent V1/V2 and all five Overworld requirements remain in effect.

The sole **1,000,000-input benchmark completed in 96.14 minutes at 173.37 seeds/s**, at the original borders with **30 Python processes × 1 native thread each**. It includes baseline prediction, worker startup and persistence; terrain and BDS costs are separate. No production sweep has started. Actual Bedrock certification remains open; the compatibility report deliberately keeps `large_search_ready=False`. The [current readiness checklist](MASTER_SWEEP_READINESS.md) distinguishes implemented engineering, optional performance decisions and open game-evidence gates.

Timings are bounded evidence, not whole-search multipliers. Existing cached land calls improved about 3.2× against the frozen reference. The one-anchor terrain replay used both variants, the first nominated center per variant and resolutions 128/64/32/16. Its imported historical anchor is a timing input, not newly established eligibility. All reported thread combinations describe measurement jobs; production terrain remains a single durable scheduler with an OpenMP team.

OpenMP was chosen because the existing C loops contain independent column work. oneTBB is a C++ task scheduler with parallel-loop facilities; integrating it would add a C++ boundary without a demonstrated benefit for these loops. No oneTBB comparison was measured. OpenMP's tested fit establishes the current choice, not a universal performance advantage.

The isolated schedule experiment attempted static, dynamic-64 and guided-64 at 18 threads. Both private alternatives reference `__kmpc_dispatch_deinit`, which the retained LLVM 17 runtime does not export; they failed to load. Setting OpenMP language versions 4.5/5.0/5.1 did not remove that reference in the local compiler probe. No ABI shim or runtime replacement was installed. Static output hashes matched across three trials on three seeds, with summed median 0.687s and range 0.684–0.690s for the land/heights/grid workload. This is a supported-build gate outcome, not a performance comparison against unavailable alternatives.

The [lower32 feasibility experiment](runs/master-implementation-2026-10-10/funnel-final/report.json) measures placement counts across the whole possible center envelope and exact joint-center intersections for all 4,096 layouts. Both rejected only 30 layouts (0.73%). A witness is an allowed integer center, not a discovered Stronghold or viable generated world. Native timing projects approximately 63 hours for the entire lower32 range before ranking/checkpoint costs. Selected siblings produced 209 predicted anchors from 160 full64 inputs versus 199 in the independent control; baseline CPU cost was 7.60 versus 7.25 seconds, with another 4.73 CPU seconds for raw selection. This small sample does not establish an advantage in verified yield. The 99.9%/45-minute promotion gate failed; keep independent full64 search primary and the raw adapter as a ranking experiment.

The saved 256-column terrain replay reproduced MAE 3.805 blocks, maximum error 39 and 71 water-proxy disagreements. Stride 1 and 8 were identical. Interpolation reduced MAE to 3.168 but retained the 71 proxy disagreements; cave/fluid probes also failed to explain them fully. These are unvalidated diagnostic models. No production sea-level inequality, cave inventory or scoring threshold was changed to manufacture accuracy. [Per-column results](runs/master-implementation-2026-10-10/terrain-attribution/columns.csv) and [report](runs/master-implementation-2026-10-10/terrain-attribution/report.json) preserve the remaining uncertainty.

The following gates stay open before an authoritative production search: exact-build structure/Stronghold recall, actual required-structure acquisition with supported coverage, complete natural V1/V2 positive/negative formation calibration, natural-ground/liquid provenance and sustained concurrent discovery/terrain/BDS resource measurements. Optional structure-contact diagnostics lack supported actual footprints. Approximate height remains a scheduling hint; the legacy coast-frontier C port and Metal remain deferred because a relevant measured bottleneck and useful-yield gain were not established.

The [pre-benchmark forecast](runs/master-implementation-2026-10-10/million-forecast.json) retained 30 baseline processes: 36 was less than 1% faster in the matched 1,000-input trials. The separate 10,000-input forecast pilot completed in 49.46 seconds (202.17 inputs/s), projecting **82.44 minutes**, a working range of **74.20–123.66 minutes**, and approximately **34.84 GiB** of database storage for the million. The [completed million report](runs/master-implementation-2026-10-10/million/benchmark.json) records **96.14 minutes**, **173.37 inputs/s**, and **34.55 GiB**. Throughput was **14.25% below** the pilot estimate and time was **16.61% longer**, within the working range. The historical 1.36–2.70-hour forecast already included Python multiprocessing. Terrain acceleration does not multiply this baseline-only rate.

The million retained **1,202,310 predicted** and **1,426,716 pending** Stronghold candidates. These are anchors, not distinct seeds or verified worlds. Peak sampled process-tree RSS plus the reserved 8 GiB Docker allowance was **12.22 GiB**, below the 25 GiB working target; this allowance is not a concurrent-BDS measurement. Benchmark wall time ends before the final qualified-pool digest/report, consistently with the forecast pilot; the read-only audit is also timed separately.

The [joined terrain table](runs/master-implementation-2026-10-10/terrain-attribution/joined-columns.csv) adds retained actual support/top block types, exposed water, discarded cover and probes. Primary/overlay fluid state and structure-cover provenance were absent from this historical observation and remain explicitly unknown; its older policy is not upgraded to current natural-ground verification.

The [read-only million audit](runs/master-implementation-2026-10-10/million-audit.json) passed database integrity, all **1,000,000 distinct signed-full64 inputs**, their exact permutation sequence and **31,250 contiguous nonoverlapping completed ranges**. It checked exact final Nether bounds for all **2,629,026 candidates** and **10,650,483 stored Fortress/Bastion starts**, with zero violations; 1,024 candidates were additionally replayed through the public Fraction-based bound helpers. No candidate was marked actually verified. Computational native/config identities matched the forecast and launch. Of 179 launch file hashes, 178 remained unchanged; the sole documented difference is a post-launch roadmap link/execution clarification, not a computational input. The audit took 18.90 minutes separately from benchmark timing.

The private Stronghold tracer records active MT state/draw positions, float/double angles, floor versus hypothetical truncation, search windows, candidate order and biome viability. All seven controls matched installed village-related starts. A same-model trace cannot establish the first divergence from exact Bedrock: the independent game trace remains missing, so the root cause remains unresolved. The initial diagnostic query exceeded the wrapper's supported scan size; rerunning bounded queries at each traced start passed, with the first failure log retained.

The requested [Overworld-border comparison](runs/master-implementation-2026-10-10/border-comparison/report.json) completed nine trials: three alternating-order trials per size on the same **5,000 distinct full64 inputs**. Discovery stayed 5000 square, Nether stayed 1024 square, and every required structure remained mandatory. Production configuration and its 2688/1024 contract are unchanged.

The smaller squares processed inputs 96.87% and 124.37% faster, but produced predicted qualifying anchors per second **15.58% and 36.86% lower**. No new qualifying anchors appeared in this cohort. Retain 2688 for current search efficiency. If a more compact playable Realm is the user's objective, change only the Stronghold-centered Overworld border first; shrinking discovery removes possible anchors, while shrinking Nether reduces room for the mandatory Fortress/Bastion pair. Smaller Overworld borders also constrain full V1/V2 formation fit.

These are baseline-only rates with startup/IPC/persistence on fresh small databases; they do not establish sustained million-input speed, terrain/BDS throughput or verified-world yield. Candidate counts are anchors, so one seed may contribute more than one. Do not project speed by area ratio or change public geometry solely from this experiment.
