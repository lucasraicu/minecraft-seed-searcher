# BDS integration and bounded evidence — 10 October 2026

Implemented a self-contained selected-observation adapter and explicit manual cave checker. Bundled tools no longer reference the external setup directory. Runtime assets, server properties, pack manifest and extraction source hashes form cache identity. Installed Docker image must match `sha256:cf479afd0ab8a8bb095f7aa71fd42064cf5ba7aff6c8a8f4f5503aac826511d8`; official build is 1.26.52.3, Script API 2.10.0, server ZIP SHA256 `f6348d84fa714d04ca194f207e89453ca6bba0a1359396475271a52a150471c6`. The image uses pinned Ubuntu 22.04. Runtime validates image identity and configured VM CPU availability before generation, uses one 4-CPU/6-GiB container with no published ports, and checks exact signed seed from the stopped-world snapshot.

`VerificationAdapter(cfg, store=None)` provides `verify`, `sample_raster`, `verify_candidate`, `verify_final_nether`, and manually called `sample_caves`. Observations are JSON-safe; terrain callers receive the shared Raster type. The persistent store counts consumed selected verification attempts and caches source/version/settings/lattice-identical observations across resumes. Selection reason and optional probability remain recorded. Reasons cover top, borderline, unusual, explicit/manual, and random low-rank audits. Callers must select from qualified baseline records; the adapter does not scan every seed or change baseline membership.

Tiles preserve the requested sampling lattice and half-open bounds, handle negative/off-grid coordinates and square edge overscan, and each touches at most 289 chunks. All tiles for a request share one disposable BDS world. Conflicting overlap samples fail rather than overwrite. Full requested lattice coverage is checked when assembling the raster. Default maximum 16 tiles deliberately defers a full 2688-square until larger-footprint cost and resource measurements justify an explicit policy change. Default selected verification budget is 20. Tile loading currently replaces active ticking areas, so generated world data is reused but previously active areas are not kept ticking indefinitely.

The ordinary path is read-only. `persist_snapshot: true` explicitly enables the disposable-world Y=319 air/glass/restore experiment, records sky restoration audits, validates every requested region's persisted chunks, and compares sampled actual blocks. The stopped snapshot is copied before database access. Within-tick native/reference comparisons and up to four bounded settling passes detect mismatches/unstable samples. Unknown sampled cells are retained as unknown. Source provenance is actual, but natural-ground structure masks, waterlogging and ice classification remain unsupported: terrain quality stays **PARTIAL**, including one-block rasters. Exposed-water observations do not certify all liquid or natural-ground semantics.

## Verification selection CLI

`verify-terrain` supports `--top N --borderline N --unusual N --random N --sampling-key K`. Every selection is from variants whose saved baseline anchor is PREDICTED or VERIFIED; pending anchors are excluded before ranking and reservoir population counting. Picks are de-duplicated by candidate/center and capped to the remaining persisted BDS attempt budget, with top, borderline, unusual, then random priority. Deterministic categories use bounded heaps and stable candidate/center tie-breaks; the random audit uses a bounded reservoir over the remaining qualified variants.

Borderline picks have at least one measured geometry channel within 25% of its normalized eligibility threshold and are ordered closest first. This is a documented threshold-proximity heuristic, not measured uncertainty. Unusual picks prioritize partial/unsupported/failed terrain data, outside/unknown formation borders, high geometry-score failures, and recorded uncertainty/truncation. The existing evidence/geometry/score ordering determines top picks. Deterministic conditional inclusion is recorded as 1; random audit inclusion is k/N after deterministic exclusions. These probabilities do not justify whole-population accuracy claims. A separate selection observation persists reason, probability, sampling key and the selection rules even if the candidate lacks a measured footprint and generation is deferred. Four focused selection tests exercise deterministic categories, qualified-only filtering, duplicate exclusion, conditional random probability, budget caps, CLI persistence and invalid counts without native/BDS launches.
