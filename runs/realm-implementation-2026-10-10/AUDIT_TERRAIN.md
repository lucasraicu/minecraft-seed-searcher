# Terrain completion audit — 10 October 2026

Read-only audit of current code and existing artifacts. No source changes, tests, native generation, BDS runs or benchmarks were performed for this audit. Only this report was written. Implementation remains held for the user's additional fixes. This is not a completion declaration.

Eight V1 centers completed; two V2 centers committed and that task remained started. This is a lower bound on interrupted cost, not a measured full-default runtime. It predates the cache patch.

These selected observations do not estimate population precision/recall.
- `terrain-cache-matched.py` and `terrain-pilot.py` are prepared scripts, not completed performance evidence. Neither `terrain-cache-matched.json` nor a full post-cache `terrain-pilot/results.json` exists. **Native cache parity, speedup and full post-cache terrain cost remain unrun.**

## Concrete correctness findings and missing requirements

These findings are from code inspection. The scenarios below were **not executed** during this audit.

| Priority / classification | Finding and concrete consequence | Source / evidence gap |
|---|---|---|
| **HIGH — correctness** | **A closed lake with unobserved opposite shores can still receive a false complete within-border footprint.** `water_body_closed` checks the component boundary, but `footprint_complete` does not require opposite-shore observations. If every ray ends before the shore, the footprint falls back to the 100-block ideal belt and is still declared complete. Analytical example: radius-160 island inside a radius-1100 lake in a fully known ±1280 raster, evaluated against a ±300 border. The ~854-block ray limit finds no opposite shore; the saved local belt is roughly radius 260 even though the relevant lake extends much farther. This must stay incomplete or measure a justified enclosing extent. | `terrain.py:126,138–140,154–163`; current lake-fit test covers only radius 400, within the ray reach |
| **HIGH — identity/resume correctness** | **Terrain task identity omits the actual native binary/backend wrapper and custom provider identity.** Hashes cover terrain/raster/biomes plus declared config, not the actual backend binary or `backend.py`; custom `provider_factory` identity is also absent. A changed implementation with an unchanged backend_commit string can silently skip completed old tasks. CLI terrain loads persisted config but does not compare current native identity before the skip. | `terrain.py:296–331,367–371`; `cli.py` existing-run/terrain dispatch; identity test changes config, not binary/custom provider |
| **MEDIUM — cache correctness** | **Actual-provider unknown/failed responses can be reused as exact-window cache hits.** The refresh guard tests only `metadata.source != 'actual'`. `VerificationAdapter.sample_raster` returns missing/failed rasters with unsupported/failed/reason metadata and no actual source, so a subsequent same-window cache request can return stale missing evidence without invoking the provider. The new refresh test covers declared source actual, not this failure path. This preserves unknown eligibility but can prevent recovery. | `raster.py:132`; `verification.py:160–169`; add a provider-first-fails-then-recovers control when changes resume |
| **MEDIUM — continuity acceptance gap** | **V2 continuity is local to two adjacent bearings, not continuity of an enclosing ridge system.** Several disconnected components, each intersecting two neighboring rays and satisfying width/area, can together supply 32 hits and gap zero. Broad isolated hills can therefore evade the tiny-spike control. Whether multiple separated arcs with passes qualify needs a stronger, explicit continuity policy/calibration; the existing radius-12 spikes test alone does not prove it. | `terrain.py:222–230`; `test_isolated_spikes_do_not_supply_enclosure` |
| **MEDIUM — actual verification planning** | **Actual verification does not always request the analysis halo needed by V2.** CLI requests the predicted formation footprint plus one sample cell. A qualifying ridge system with footprint halfwidth below 850 then fails V2's full-extent check because the actual raster does not cover center±distance_max. The real formation may fit, but evaluation remains pending because the request omitted required analysis coverage. | `cli.py:278–287`; `terrain.py:244–247`; no complete actual V2 fixture |
| **MEDIUM — score consistency** | **Direct actual evaluations ignore configurable overall weights.** `_finish` hardcodes 80/10/10; `run_terrain` corrects that afterward, but the CLI's actual-evaluation call does not. Actual evaluations also reuse predicted biome fit. A custom or rescored policy can therefore produce inconsistent actual versus predicted scores and provenance. Current natural-ground PARTIAL status prevents an actual finalist but does not fix descriptive score arithmetic. | `terrain.py:103,410–411`; `cli.py:287–289` |
| **Requirement incomplete — resumable work** | Only the selected center budget is saved. Remaining coarse proposals/results, pending finer resolution work and halo-expansion tasks are not persisted as schedulable units. The aggregate task becomes complete after its finite budget even when result pending_work says expansion/fine work remains. Changing the budget then changes algorithm identity and requires a separate checkpoint; there is no exposed continue-remaining-centers workflow. | `terrain.py:382–408,430–431`; current tests prove bounded task completion, not resuming remaining refinement/halo work |
| **Performance incomplete — partial resume** | A partially committed variant redoes each selected center's sampling and evaluation before `get_variant` checks whether its final center is already saved. Complete aggregate tasks skip generation, but partially completed tasks repeat committed-center generation. | `terrain.py:393–424`; partial native V2 task provides a realistic future restart control |
| **Requirement incomplete — declared pool revision** | Both tasks are created from the same candidate records, but a named fixed pool revision/membership snapshot is not persisted. Separate variant invocations can observe a growing candidate table. This is distinct from the implemented shared per-candidate task membership. | `store.py:199–202`; `terrain.py:361–362`; no pool revision identifier in either source |
| **Requirement incomplete — access metric** | The labeled access score is angular enclosure again: V1 uses water_rays/rays and V2 uses (rays−largest_gap)/rays. It does not separately measure approach routes, usable passage width, headroom or equivalent access evidence. Roughness must remain allowed, but the access/usability category needs a declared meaningful measurement or an honest renamed policy. | `terrain.py:176,255`; no access-route synthetic fixture |
| **Evidence unverified — metric precision** | Ray width is a count of resolution-sized samples, not exact fractional shoreline intersections. Even block-resolution actual data does not by itself remove ray-interval rounding near strict width thresholds. Narrow-bridge proof is improved by full land labeling, but width-threshold certificate precision still needs bounds/calibration. | `terrain.py:77–87,136`; fractional-area test does not cover fractional ray crossings |

## Actual-backend dependent or explicitly unverified

The official pinned BDS runtime and tiled extraction interface are available; this is not an unavailable-runtime claim. Tiling is implemented in `verification.py:76–90,110–134`, with a finite tile/attempt budget. The remaining work is natural-ground provenance (structure masks), waterlogging/ice classification, adequate actual analysis coverage, and complete V1/V2 formation fixtures/calibration at useful scales. The current extractor deliberately sets natural_ground false (`verification.py:317–321`), so current real observations cannot meet Raster's VERIFIED certificate. Synthetic verified controls demonstrate the grade gate, not an actual verified formation.

Population precision/recall, narrow unseen bridge false negatives, rare formation yield, and production terrain backlog cost are unmeasured. The selected coastal diagnostic's 71/256 land/water disagreements make aggressive predictor pruning unjustified; preserving every baseline survivor remains necessary. Native cache all-channel parity/speed and a full post-cache default cost are still pending. No additional implementation or verification was authorized/performed by this audit.
