# Engineering audit: active Master Seed Blueprint

Audit date: 2026-10-12. This report covers production source, native bridge, scheduling and evidence semantics. The bounded measurements collected by `scripts/benchmark_blueprint.py` are reported separately by the coordinating audit. Historical benchmark rates are not treated as rates for this changed contract.

## Contract correction

The former default configuration did **not** implement the supplied blueprint: it required one Village/Trial Chamber/Ancient City/Mineshaft, two wooded families at Y=63, optional Monument and several explicitly excluded structures. Its V1 described an island and V2 a mountain enclosure. Those defaults cannot support claims about five villages, all required biome families, or a Coastal Continent.

The active CLI now loads `blueprint_config()`, and `config/realm.yaml` declares `contract: master_seed_blueprint_v1`. Saved schema-5 configurations without that marker retain the old behavior. `default_config()` remains a historical compatibility constructor; callers implementing the active task should use `blueprint_config()`. Schema-3/4 routes are retained. No checkpoint or saved island V1 was silently migrated.

The new baseline requires the exact count floors in the blueprint, including Ocean Monument (omitted in its pipeline diagram but required in its table), all three cave predicates and separate peak/shore predicates. Stronghold-centered bounds remain half-open and exact fractional Stronghold/8 Nether geometry is preserved. Broad initial Nether Fortress enumeration has no relevance to the final centered requirements and is omitted in the active path. Every discovered Stronghold receives a separate evaluation; this does not imply complete discovery recall or the Java-style three-Stronghold guarantee.

Only required structures and optional Outpost enter the active inventory. Excluded structures, End sampling and Nether biome diversity are not automatically evaluated. Smart ranking counts extras rather than once-per-family presence. Trial/Ancient City/temple/Monument/Fortress/Bastion bonuses follow the specified caps; Village/portal/shipwreck/Mineshaft extras retain per-copy rewards. Full required predictor inventories and outposts are obtained only for full baseline survivors. The additional monument-footprint bonus remains pending verified actual bounds and containment; it is not inferred from a start coordinate.

Legacy inventory completion and rescoring would otherwise overwrite the blueprint with presence-based scores and the old wooded-family gate. Explicit dispatch now preserves the count contract, restricts inventory to allowed structures, and keeps the four-Y biome policy. New candidates do not enqueue old presence-inventory tasks.

## Dashboard and API are demonstrations

`web-ui/src/App.tsx` imports `MOCK_CANDIDATES` and fabricates throughput, candidate seeds and status updates with `Math.random`. Its historical V1/V2 labels and displayed generation/verification claims are mock data, not scan evidence. `web-api/main.py` likewise produces random WebSocket telemetry; `/api/start-sweep` only toggles a module boolean and prints a request, and its own TODO identifies the missing bridge to `realm/runner.py`. Neither component queries the production SQLite leaderboard or launches the production search. Therefore the blueprint's interactive live dashboard/export integration is **not implemented**; production search and truthful results are available through the CLI, SQLite, JSONL and CSV. Displayed millions-of-seeds-per-second demo rates must never enter benchmark or feasibility claims.

## Native and parallel execution

| Area | Finding and disposition |
| --- | --- |
| Native count floors | New public `ss_structure_count` / `Backend.structure_count` returns at most N distinct viable predictor starts. It exits when the floor is reached, labels count completeness separately, and supports Mineshaft's native SIMD scan. It is compiled through the production CFFI build. |
| Prior pilot kernels | Diagnostic private count libraries and their mutable direct-mapped cache are not runtime dependencies. The promoted kernel has no shared global cache and never reuses low-bit biome/viability evidence. |
| Mineshaft | Existing vector kernel preserves the pinned low32 model; its stopping argument now supports N rather than only one. A result at N is a lower-bound witness inventory, not a census. Under-floor scans exhaust the bounded predictor query, never actual-world coverage. |
| Python/native bridge | CFFI uses contiguous bounded arrays; wrapper validates floors, coordinates, dimensions and closed handles. The process-local reentrant lock serializes Python threads accessing handles. CFFI releases the GIL during native work, but this lock means Python threads are not a substitute for the current process pool. |
| OpenMP | Immutable generator/noise reads are parallelized over columns/points; initialization happens before the parallel region. Native batch threshold is 256, with static scheduling and per-handle thread count. Active first-N regional structure scans remain serial within each process. |
| Oversubscription | Spawned processes receive numeric-library limits of one and the configured native thread count; the process × native-thread product is capped at 36. Baseline uses process parallelism; terrain is a separate configured native workload. An OpenMP build does not make all stages parallel. |
| Build portability | Portable serial build is the default; optional OpenMP requires explicit runtime prefix and matching macOS host architecture. Existing local OpenMP builds depend on their supplied `libomp` prefix; moving/deleting that prefix requires a serial rebuild or a replacement explicitly pinned runtime. No AVX-only build flag was added. |
| Process scheduling | Parent owns durable range leases and SQLite commits; outstanding batches are bounded by worker count. Spawn avoids sharing mutable generators. Source/config/native identities and canonical signed-64 seed strings remain in checkpoint semantics. |
| Throughput interpretation | Native kernel rate excludes worker startup, Python record construction, JSON serialization, SQLite commits and resource monitoring. The parent/persistence path can dominate a very selective filter; only persisted full-seed measurements support end-to-end rates. |

The historical diagnostic builder also depended on a literal `n<0 || first` source replacement. After the production stopping condition gained count-floor semantics, that replacement no longer matched: a freshly rebuilt pilot could overflow its retained Mineshaft prefix even while tests against the old frozen binary passed. `scripts/build_count_pilot.py` now injects an explicit cap return immediately after both emit sites, validates expected source shape, imports without build side effects, records its own source hash, and accepts `--output` for isolated rebuilds. The fresh-build regression compiles in a separate directory/interpreter and checks positive raw and biome-qualified caps against complete inventories; frozen evidence binaries and identities remain untouched. The isolated build/source tests passed (2 tests, 7.30 seconds); its 405 count comparisons included 144 raw over-cap and 45 biome-qualified over-cap positive cases with zero mismatches. Evidence: `runs/blueprint-audit-2026-10-12/count-pilot-build-test/test_fresh_count_pilot_build_p0/fresh-native/identity.json` and `parity.json`.

Source-distribution packaging also had a concrete defect: `MANIFEST.in` omitted `native/*.inc` even though `bridge.c` includes `filters.inc`. The manifest now packages native include fragments, with a file-list expansion smoke test. Computational identities now include `blueprint.py` and `coastal.py`, and capability metadata reports the selected contract/variants and the limited coastal certification scope.

No speculative raw-capacity gate was promoted: it would repeat placement and can retain too many inputs to justify its cost. The active order begins with scarce Mansion/Jungle Temple/Desert Pyramid/Monument evidence, then the denser floors and Mineshaft. Reordering may be measured later without changing the required set. Native floor timing, complete-reference timing and total persisted scan timing are recorded separately in the bounded audit.

Stage timers are `stronghold`, `structure_<name>`, `final_nether_pair`, `final_<name>`, `biome_palette_4y`, and `ranking_inventory`. Counters include each checked structure, unmet floor, structure-stage entry/pass, Nether-stage entry and biome-stage entry/pass. Worker CPU, inclusive native calls, wall time, RSS and cache hits remain available. Timers for an early-exited stage are absent, not zero measured work at a stage that ran.

## Biome and terrain correctness

Four-Y sampling uses a world-aligned 64-block lattice at Y=63, -48, 0 and 160. Surface-family witnesses are accepted only at Y=63/160 and cave-family witnesses only at Y=-48/0. Sampling interleaves Y layers at dispersed XZ positions, caches exact full-seed points across overlapping anchor borders and can stop when every required family has a positive model witness. Full reference mode evaluates the whole declared lattice. A complete defined lattice is still not exhaustive block coverage.

Pale Garden cannot satisfy Dark Forest, sparse jungle cannot satisfy the stricter Jungle/Bamboo predicate, broad mountain families cannot replace Jagged/Stony Peaks, and Stony Shore is a separate requirement. The pinned Mansion viability model admits Pale Garden, so Mansion count observations inspect all predicted starts and retain Dark Forest witnesses at Y=63. This is a documented conservative model policy: a genuine Dark Forest surface mansion can remain pending if its fixed-Y sample is a cave or otherwise differs from its surface biome. It must not be counted as actual absence.

The preexisting exact 3D Voronoi/block-to-quart transform, negative coordinate floor division and per-point biome tie handling remain intact. No nearest-leaf hint or high32 sibling biome reuse was introduced. Terrain's cached eight-Y raw-noise term and quart-column deduplication preserve the pinned raw-density expression; coarse vertical stepping can miss thin overhangs and the stride-one path is the exact raw-model reference. Raw density still omits Bedrock's complete cave, aquifer, decoration and chunk-interpolation generation behavior.

V1 Coastal Continent is a new explicit mode, not a rename of island V1. Its evaluator measures connected primary land area against the full 1536² border, connected ocean strip/sector geometry and a conservative predicted monument envelope. Active `all` scheduling follows `terrain.variants=['v1']`; historical V2 remains inspectable and resumable under its old profile. A 250-block strip along a continuous half-edge is the operational coastal-quadrant interpretation. The 400-block value is a preference rather than an upper eligibility cutoff. The ±80-block monument envelope is an engineering screening envelope, not a measured actual footprint.

Coastal results explicitly scope themselves to a geometry subset. Actual sheer sea cliffs, rolling topography/no enclosing wall, full resource availability (including packed/blue ice), generated cave structures and precise monument footprint remain unresolved unless separately observed. The pipeline does not claim a fully certified blueprint world from four fixed Y planes or a raw terrain raster.

## Verification

New focused blueprint tests cover active versus historical validation, exact family conjunctions, Y-role separation, full reference versus early-pass equivalence on a passing fixture, pending/early-exit semantics, complete-count bonus caps and native count/full-inventory parity. The native parity corpus includes 0, 12345 and -1 across Village, Trial Chamber, Ancient City, Mineshaft, Shipwreck, Ruined Portal and Mansion. The expanded 27-test blueprint suite passed in 3.03 seconds, adding full64 extreme/sibling seeds, negative/boundary coordinates, inventory/rescore protection, capability/source-identity coverage, native source-distribution include expansion, exact passing-fixture witness/count/score parity and individual failures for all twelve non-anchor required floors. The coastal engineering branch additionally reported 112 passing focused/historical geometry tests; final integrated suite results are recorded by the coordinating audit.

These tests establish implementation invariants against the pinned predictor and synthetic geometry, not actual Bedrock precision/recall or the blueprint's asserted 1-in-1.5-million rarity. Small zero-hit scans cannot establish that probability or a 35–50-minute expected time. No full production search, BDS campaign, or actual seed certification was performed as part of this engineering change.

Final integrated suite: **773 passed in 109.31 seconds**. One old profile-equality test was updated to distinguish the active coastal constructor from the preserved historical island/mountain constructor; its historical preference assertions remain covered. Explicit `config/realm.yaml` retains the established 18-thread isolated terrain profile; the portable no-config constructor uses one terrain thread. CLI compatibility/status checks and final computation-identity parity passed. The full measured throughput, kernel comparisons, cleanup receipt and realistic conditional planning scenarios are in [BLUEPRINT_BENCHMARK_RESULTS.md](BLUEPRINT_BENCHMARK_RESULTS.md). The 30-worker persisted baseline measured **1,238.229493 input seeds/s** over 30,000 distinct inputs; no full baseline survivor reached the biome/coastal stages.
