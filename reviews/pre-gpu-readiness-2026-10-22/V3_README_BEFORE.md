# Catalog v3: sampled biomes and per-objective reserves

Implementation, migration acceptance and public adoption are complete.
See [the release report](../../../reviews/biome-expansion-plan-2026-10-22/RELEASE_REPORT.md) for measured verification and limits.

V3 adds 56 exact Overworld choices, four declared ANY-member groups, the five existing Nether choices, source-bound height extensions, and a ranked 2K membership sequence for every finite public objective. Shared observations remain in SQLite/CAS once per world. Primary/reserve position belongs to each objective; Personalized Selection always queries the retained union.

The checked-in registry is a conservative template: 46 core choices enabled, ten height-dependent choices and both contextual structures gated. The prepared 2026-10-22 migration uses its own immutable activation registry enabling all 56 exact choices after archived and fresh BDS controls plus the height-cost pilot. Snowy Beach is restricted to Y63 because additional-height controls disagreed. Igloo basement and treasure bastion remain gated because compatible independent variant controls are missing. A name/version match alone does not activate a capability.

Queries use `catalog-query-v3` and `predicted_observations_v3`, bound to the selected snapshot's registry/profile/source IDs. A biome row's alternatives are OR (maximum16); separate required rows are AND around the same anchor (maximum12rows). Groups retain declared atomic members. Missing samples are UNKNOWN. XYZ identifies the sampled height, with no terrain surface, player landing, safety, exhaustive absence or physical-instance count guarantee. The compact UI searches and expands groups/categories and displays witness heights.

V1/V2 requests, decoders, historical snapshots, share links, and legacy Y63/Y64 biome aliases remain supported. Historical snapshots reject unsupported V3 choices with a capability error. New heights live in separate observation-bound CAS extensions; the original observations, Realm inputs and evaluations are unchanged. Public scoring remains845/265/140, borders2048/4096/8192, fixedNether1024. All existing IPC/artifact/query/resource limits remain in force.

The public contract contains7543objectives,115964primaryslots and231928retainedslots. These are aggregate membership bounds, not unique-world counts or an assertion that every list has enough candidates. Boards default to primaryK, expose an optional reserve view, and bind pagination to snapshot/objective/view. Candidates remain predicted until their exact advertised scope has actual-game evidence. Migration reuses the saved222world cohort and marks historical reserve completeness false; previously discarded worlds cannot be recovered without a separately authorized search.

New personal native-pipeline runs with `top_k=50` retain100distinct seeds throughout screening and show50primary by default. The pruning cutoff starts only once the effective2Kcapacity is full. JSON caches, authoritative SQLite and checkpoint identity record winner limit, effectivecapacity and reservefactor. Historical resumes preserve the recorded capacity and cannot silently expand. New targetK>500 is rejected under the existing1000candidate limit. The candidate API accepts `view=primary|reserve`; the personal UI exposes this only when the run supplies reserve metadata. Installing this code does not change a running historical personal server or checkpoint.

Explicit finalist advancement uses `seed_search.catalog.finalization_operator.finalize_objective`. It takes an immutable snapshot/objective, an explicit verifier context, the existing scoped game-verifier callback and a finite check budget (default0). It visits frozen rank order, counts actual passes towardK, advances past scoped failures, and keeps errors/inconclusive results pending. It stores receipts/progress in existing `automation_meta` and protects in-progress worlds. It does not launch a second scheduler or automatic campaign. Reference samples, which have no winning layout, require an explicitly declared inspection anchor/border; product and historical layout anchors are resolved from saved bindings.

The context names actual build/provider/profile/dimension/evidence policy and the advertised `requirements`, including `objective_id` and `policy_revision`. Physical conditions are separate from those list labels for receipt reuse. Evidence identities also bind seed/source observation, anchor, border, settings and dimension: compatible physical conditions may reuse actual receipts across lists; a failure does not blacklist the seed elsewhere. Pass/fail receipts require actual BDS proof references for that scope. A prediction or bare `pass` string cannot certify a finalist. The operator's trusted verifier must evaluate every advertised condition and retain its underlying artifacts. Budget exhaustion and insufficient retained passes leave an explicitly incomplete result.

Run bounded migration with `scripts/migrate_catalog_biomes.py --source ... --destination ... --registry ...`; `--resume` uses the same frozen inputs and durable cumulative allocation. Use only an approved cohort and disjoint destination. This release authorizes no large search or automatic BDS campaign. The old public root remains a rollback source.

Evidence, measured costs, stronghold investigation, independent review reconciliation and release validation are recorded in `reviews/biome-expansion-plan-2026-10-22/`. The portable actual-game archive is `fixtures/bedrock-26.52/biome-expansion/evidence-v1.tar.gz`, with per-member checksums in `manifest.json`.
